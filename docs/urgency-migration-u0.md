# U0 canonical urgency migration

Prepared 2026-10-07; the coding agent has not executed any migration or tests.
Canonical values: `routine`, `urgent`, `emergency` (Routine / Urgent / Emergency).

## Schema and data change

Repository inspection found an ENUM in historical migration
`008_create_blood_requests.sql`: `routine`, `urgent`, `critical`, NOT NULL,
default `routine`. That migration stays unchanged. Live schema inspection is
left to the operator; the preflight below prints the actual column definition.

New migration `019_canonical_emergency_urgency.sql`:

1. Enables strict session SQL mode and appends `emergency` to the existing ENUM.
2. Updates every `critical` row, including closed/expired requests, to `emergency`.
3. Checks that every row has a final canonical value using an enforced temporary CHECK.
4. Sets the final ENUM to `routine`, `urgent`, `emergency`.
5. Asserts zero `critical` rows, removes the temporary table, restores SQL mode.

Rows, IDs, relationships, status, and timestamps are preserved. Existing matches,
notifications, and append-only audit history are retained; no notifications or emails
are generated by this migration. Already-delivered notification text and historical
audit payloads are historical records, not rewritten by U0.

MySQL/MariaDB DDL auto-commits. Stop the backend and all request-writing jobs during
execution, and back up the database first. The migration can be rerun after partial
failure; do not follow the generic runner's suggestion to drop the database.
The CHECK assertion requires MariaDB 10.4 (the documented XAMPP baseline) or
MySQL 8.0.16+ with CHECK enforcement enabled.

## PowerShell execution

Run from the repository root. These commands use the project's `.env` through
its existing PHP database configuration; they never print credentials.
Adjust the PHP executable path only if XAMPP is installed elsewhere.

```powershell
Set-Location 'C:\Users\PC\OneDrive\Documents\BloodMatch'
$php = 'C:\xampp\php\php.exe'

# Read-only preflight: save counts and inspect the actual ENUM.
& $php .\database\verify_urgency.php
if ($LASTEXITCODE -ne 0) { throw 'Urgency preflight failed' }

# Apply pending migrations through the standard migration ledger.
& $php .\database\run_migrations.php
if ($LASTEXITCODE -ne 0) { throw 'Migration failed; keep writers stopped and inspect the error' }

# Read-only postflight: nonzero exit on schema/data/ledger mismatch.
& $php .\database\verify_urgency.php --expect-emergency
if ($LASTEXITCODE -ne 0) { throw 'Urgency verification failed' }
```

The runner applies **all pending numbered migrations**, not just 019. Check
`schema_migrations` first; with 001–018 recorded, only 019 will run. If earlier
migrations are pending, review those before running the command.

Compare preflight/postflight: `total_rows`, `routine_rows`, and `urgent_rows`
must be unchanged; postflight `emergency_rows` must equal preflight
`emergency_rows + critical_rows`. Postflight `critical_rows` and `invalid_rows`
must both be zero, and `migration_applied` must be true. Restart the backend
with the updated application after successful verification.

## Equivalent read-only MySQL checks

Run in the database configured in `.env`:

```sql
SHOW COLUMNS FROM blood_requests LIKE 'urgency';
SELECT urgency, COUNT(*) AS rows_count FROM blood_requests GROUP BY urgency;
SELECT COUNT(*) AS critical_rows FROM blood_requests WHERE urgency = 'critical';
SELECT COUNT(*) AS invalid_rows FROM blood_requests
WHERE urgency IS NULL OR urgency NOT IN ('routine', 'urgent', 'emergency');
SELECT name, applied_at FROM schema_migrations
WHERE name = '019_canonical_emergency_urgency.sql';
```

Expected column type: `enum('routine','urgent','emergency')`, NOT NULL, default
`routine`. Expected retired/invalid row counts: **0**.

## Remaining old-term classification

The repository scan uses case-insensitive `critical`, including hidden files and
ignored source files, excluding Git internals, dependencies, and generated builds:

```powershell
rg -n -i --hidden --no-ignore -g '!.git/**' -g '!**/node_modules/**' -g '!**/vendor/**' -g '!**/dist/**' critical .
```

Remaining occurrences are classified as:

- Historical schema: migration 008.
- Migration conversion/checks and this execution guide: intentional old-value references.
- Read-only verifier: counts and rejects legacy persisted values.
- Negative regression tests: intentionally submit/reject the retired value or assert its absence.
- Third-party PHPMailer: `STOP_CRITICAL` and error severity, unrelated to request urgency.
- Generic engineering/security wording in project docs: architectural importance,
  security severity, missing-feature severity, and selector integrity.
- Bundled agent skills/data: generic review severity, security examples, performance
  terminology, and spring damping; unrelated to request urgency.

There should be no active urgency logic, UI, positive fixtures, or urgency-domain
documentation using the old value. Historical database notification/audit content
is not part of a repository source scan.
